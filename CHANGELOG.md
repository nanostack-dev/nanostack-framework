# Changelog

One section per module and version, newest first. Each section uses Added, Changed, Deprecated, Removed and Fixed. [RELEASING.md](RELEASING.md) gives the release steps and the upgrade notes.

## Unreleased (gen)

### Added
- `nano gen api` and the pipeline's api step (package `gen/api`): oapi-codegen v2.8.2 runs in-process, with the `oapitemplates` overrides, and writes the std-http strict server and each Go client that `nanogen/project.go` declares. The output is byte for byte what oapi-codegen's command writes, after a `Code generated by nano gen api` header. A binary that resolves another oapi-codegen, or replaces it, exits 3 with the `go get` fix. A client's `PlainTypes` drops the server's `x-go-type` hints, as anchor's `client-spec.sh` did. A remote `$ref` is an error. The pipeline runs api first and rejects a `//go:generate` line that runs oapi-codegen.
- `nano gen` with no generator name runs the pipeline (package `gen/pipeline`): it reads `nanogen/project.go`, discovers the `//nano:errors` catalogues and the `nano.Manifest` packages, and runs validate, errors, config and wire in that order. `-check` writes nothing and lists every stale, missing or orphaned file; `-diff`, `-json`, `-list`, `-only`, `-skip` and `-dir`. An unknown `//nano:` directive and a `//go:generate` line that runs `nano gen` are errors ([ADR 0023](docs/adr/0023-nano-gen-pipeline.md)).
- `gen/validate`: the `x-nano-unenforced: "<reason>"` schema extension accepts the unenforced features of that schema and of the schemas under it. `Result.Gaps` returns the gaps that no extension accepts and the extensions that accept nothing. `Diagnostic` has `Line` and `Waived`.
- The module `github.com/nanostack-dev/nanostack-framework/gen`: the generators (`gen`, `gen/config`, `gen/errors`, `gen/validate`, `gen/wire`, `gen/api`, `gen/jet`) and the `nano` CLI at `gen/cmd/nano`. Its tags are `gen/vX.Y.Z`, cut after the root tag ([RELEASING.md](RELEASING.md)). A service pins the CLI with `go get -tool github.com/nanostack-dev/nanostack-framework/gen/cmd/nano@<tag>` and runs `go tool nano gen <name>`.

### Removed
- `gen/oapi` (`Config`, `ServerCodegenYAML`, `ClientCodegenYAML`, `DefaultServiceConfig`), which v0.23.0-beta.1 shipped in the root module. Declare the spec, the server and the clients in `nanogen/project.go`, and delete the oapi-codegen configuration files and `//go:generate` lines.
- `nano gen validate -allow` and `genvalidate.Options.Allow`. Move each acknowledged pointer to an `x-nano-unenforced: "<reason>"` extension on that schema in the spec.

## Unreleased (root)

### Added
- `core/nano/project`: the types of the project declaration, `nanogen/project.go`, that `nano gen` reads (`Project`, `OpenAPI`, `Package`, `Client`). `OpenAPI.Clients` lists the Go clients; `Package.File` names the server file (default `api.gen.go`).

### Removed
- `gen/...` and `cmd/nano` leave the root module for the `gen` module. `go run github.com/nanostack-dev/nanostack-framework/cmd/nano` no longer resolves; RELEASING.md, "Upgrade from v0.23.0-beta.1", gives the `tool` directive and the `//go:generate` change. The `gen/...` import paths do not change.
- The root `go.mod` no longer requires `golang.org/x/tools` or `github.com/oapi-codegen/nullable`.

### Changed
- `internal/layers`: the tooling layer is the `gen` module (`Tooling`); `cmd` is no longer a layered tree.
- CI: a `gen` job (vet, test, `go mod tidy -diff`, `lintconfig -check -dir gen`, lint), `gen` in the govulncheck matrix, and `go mod tidy -diff` in the root. `release.yml` checks `gen/go.mod` and `gen/vX.Y.Z` tags.
- CI runs `nano gen -check` on `internal/nanoexample`, which has a `nanogen/project.go` and no `//go:generate` lines.
- `http/nanohttp/internal/example` declares its spec in `nanogen/project.go`; `nano gen` writes its `api.gen.go`, and CI runs `nano gen -check` on it. Its `oapi-codegen.yaml` and `//go:generate` lines are gone.

## v0.23.0-beta.1 (root)

### Added
- `core/` (secret, log, config, fault, validate, nano), `http/` (problem, nanohttp), `gen/` and `cmd/nano`.
- Nano modules: `core/logging`, `otel/nanotrace`, `pg/nanopg`, `pg/nanomigrate`, `pg/nanolock`, `redis/nanocache`, `http/nanoserver`, `http/nanoapisec`, `http/nanopprof`; the `modules/nanofx` bridge. `modules/apisec` is a thin wrapper of `http/nanoapisec`. [docs/modules.md](docs/modules.md) lists them.
- `core/log`: `Config.Wire` (`WireLegacy`) and `ParseWire`, `Settings`, `ContextAttrs` (attributes read from the context of a record), `HTTPOptions.LegacySummary`, exported summary keys.
- `http/problem`: `NotFound`, `MethodNotAllowed`, and `MissingParameter` (a required parameter is absent; the generated parameter binding keeps its error as the cause).
- `http/nanohttp`: `NewRouter` (ServeMux with chi-compatible HEAD, 404 and 405 answers). The generated `NewHTTPHandler` takes `HTTPHandlerOptions.RequestErrorHandlerFunc` and `ResponseErrorHandlerFunc`; they default to `nanohttp.RequestError` and `nanohttp.ResponseError`.
- `http/nanoserver`: `Readiness` (`NewReadiness`), the App's readiness as a `pkg/health` check for `/health`.
- `nano.AppConfig`: `config` tags (`start_timeout`, `stop_timeout`, `health_timeout`) for `nano gen config`.
- `pkg/httputil/errorenvelope`: the writer of the legacy error envelope (`{"errors":[{code,message,metadata}]}`, `application/json`) for the strict hooks and the router, on the oapi-codegen chi strict server and on the nano HTTP stack. `Writer` logs the `request failed` line through `core/log` with the request scope (`request_id`). A service that moves its logging to `core/log` replaces `StrictErrorHandler` with `errorenvelope.New(...).RequestError` and `ResponseError`. Boundary errors render as `<location>: <detail>` with metadata `field` and `rule`, not as kin-openapi text: update the gate assertions on that text first ([docs/http-boundary.md](docs/http-boundary.md)).
- `internal/layers.Leaves`: `pkg/functional` is the leaf layer, and `core/`, `gen/` and `cmd/` may import it.
- `.github/workflows/release.yml`: the go.mod release check on every pull request, and a scratch consumer build for each release tag.
- Beta audit fixes (2026-11-08, see the [decision log](docs/decision-log.md#2026-11-08-beta-audit-fixes)): `nanoserver.Draining(ctx)`, the channel a long-lived handler selects on to end its stream when the drain starts; `nano.AppConfig.DrainDelay` (`APP_DRAIN_DELAY`, default 0), the time Stop keeps the Runners serving after readiness turns unavailable (Start fails when it leaves the Runners less than `StopGrace` of `StopTimeout`, and a Stop context cancelled during the drain ends it); `DefaultConfig()` in `pg/nanopg`, `pg/nanomigrate`, `pg/nanolock`, `otel/nanotrace`, `http/nanoserver` and `http/nanopprof`, kept equal to the `default:` tags by `core/config/configtest.AssertDefaults`; `nanofx.Context(ctx)`, the `context.Context` that the dialing constructors take on fx; `nanotrace.Installer` (`NewInstaller`); `pkg/tracing.WithEndpointURL`; `core/log.ResponseStatus`; `apisec.MatchChi`, `apisec.ExplicitHEAD` and `nanoapisec.NewResolverWith`; `nanohttp.ReadText`; `validate.MaxErrors` with `Errors.Full`, `Truncated` and `Listed`.
- CI: a govulncheck v1.9.0 job for the root, `pkg/functional`, `db` and `db/tests`; the release consumer build waits for it.

### Security
Beta audit fixes. Each one that changes a response or a log line is listed with the change.
- **Bounded validation errors (sec-http-1).** A request body with many violations (a 1 MiB array of empty items, an object of unknown members) built one error per violation: about 900 MB of allocation for one request. Generated validation now stops at `validate.MaxErrors` (100) plus one, skips the items of an array past `maxItems` and the members of an object past `maxProperties`. Wire change: a 422 or 400 lists at most 100 violations, and its detail says "More than 100 violations in the request body; the first 100 are listed." instead of the count. Responses with 100 violations or fewer do not change.
- **Security requirements match the router (sec-http-2).** `pkg/apisec.Resolver` matched with gorilla/mux, which treats `servers`, encoded paths and HEAD differently from the router that serves the request, so a request could reach an operation under the requirements of another one. `apisec.NewResolver` now matches as `http.ServeMux` and `nanohttp.NewRouter` do (`ExplicitHEAD` refuses HEAD on a GET route as the router does); a service on chi passes `apisec.MatchChi()`, which matches as chi's `Find` (raw path first). `modules/apisec` uses `MatchChi`. The `servers` entries are ignored. A spec whose paths conflict in ServeMux, or that has a parameter inside a path segment, fails `NewResolver` without `MatchChi`. Echopoint tests that call `apisec.NewResolver(doc)` pass `apisec.MatchChi()`. A request the resolver does not match must be refused (the doc says so); echopoint's `WithAuth` must do it before the service adopts `NewRouter` or drops its kin-openapi validator.
- **Text bodies are bounded (sec-http-3).** A `text/plain` request body of a generated nano server was read without a limit. It now reads through `nanohttp.ReadText`, under `DefaultMaxBodyBytes`, and an oversized body is a 413, as for JSON.
- **Generated code cannot be injected from the spec (sec-supply-01, sec-supply-02).** `nano gen validate` copied spec text (a `format`, a type name, a discriminator mapping, a path) into Go comments, where a line break ended the comment and the rest compiled as code. It now escapes control characters and U+2028/U+2029. A boolean enum value written `True` or `yes` is decoded as YAML decodes it, and a non-numeric value in a numeric enum is a spec error instead of generated code.
- **Dependencies (sec-supply-03).** OpenTelemetry v1.47.0 (contrib v0.72.0), XSAM/otelsql v0.44.0 and klauspost/compress v1.20.3, past the advisories that govulncheck reported as reachable. `db` and `db/tests` declare `toolchain go1.27.3`. govulncheck now reports no reachable vulnerability in any module, and CI keeps it so.
- **Readiness hides check errors (sec-core-02).** The `/readyz` body of `nano.App.AdminHandler` named each failing check with its error text, which can carry a host name or a DSN fragment. Wire change: each check now reads `ok` or `fail`. The error goes to the log, once when a check fails or its error changes (Warn) and once when it passes again (Info). Serve the admin handler on its own listener; the wire example does.
- **Redaction (sec-core-01, sec-core-04).** `secret.RedactURL` redacts the whole text of a URL that parses into a host ending in `:` or an `@` in its path or fragment (a password with an unescaped `@` or `#`), and of an opaque URL; `config.ParseURL` rejects a host that ends in `:`. `secret.IsKey` also treats the suffixes `sig`, `pwd`, `jwt` and `passcode` as secret, and judges the last segment of a bracketed key (`user[password]`, `items[0][token]`). More values are redacted in logs; none is redacted less.
- **Cache keys have one encoding (sec-db-001).** `redis/nanocache` joined key parts with `:` without escaping and passed them into a Redis glob, so `Key("a:b")` and `Key("a", "b")` were one key, and `EvictPrefix("team[ops]")` or `EvictPrefix("*")` evicted the wrong scope. A part's `:` and `\` are now escaped, `EvictPrefix` escapes the glob characters, and `EvictPattern` unlinks each SCAN page instead of one unbounded DEL. Keys whose parts hold neither character (UUIDs, hashes) do not change; others start cold after the deploy. `nanocache.New` now returns `(Cache[T], error)`: it rejects an empty prefix and a prefix with a glob character or a trailing `:` (`ErrInvalidPrefix`), and two caches must not have nested prefixes (`a` and `a:b`). `modules/cache` is frozen and keeps the old keys.

### Changed (breaking)
- `pkg/db/transactor` and `pkg/jetx` take Nanostack DB types (`github.com/nanostack-dev/nanostack-framework/db/...`) instead of go-jet. Rewrite go-jet imports and regenerate models.
- `pkg/functional` is its own module (same import path). `go mod tidy` adds it.
- The root module requires `db` and `pkg/functional` at tagged versions and no longer requires `github.com/go-jet/jet/v2`.

### Changed
- `modules/httpserver.StrictErrorHandler` uses the resolution of `errorenvelope`. Its answers for v0.22.0 inputs do not change, with three additions: a `core/fault.Described` error (a generated catalogue error) gets its own status and its code in upper case instead of 500 `UNEXPECTED_ERROR`; an `http/problem` request error of the nano HTTP stack gets one detail per field error (`<location>: <detail>`) and keeps 413 and 415, instead of the problem's `Error()` text in a 400; an `AdaptError` that returns `(nil, true)` counts as no match (500 `UNEXPECTED_ERROR`, logged as unhandled).
- `modules/apisec` is a thin wrapper of `http/nanoapisec`. Its fx signature does not change.

- Beta audit fixes, behaviour (see the [decision log](docs/decision-log.md#2026-11-08-beta-audit-fixes)):
  - `http/nanoserver` and `http/nanopprof`: a drain that reaches `shutdown_timeout` closes the remaining connections, logs a Warn line and returns nil. Before, `Run` returned the deadline error and a planned stop with a connected SSE client or a running CPU profile exited 1.
  - `core/nano.Main` exits 0 when SIGINT or SIGTERM arrives during the build and the build failed only from that cancellation (nanomigrate's `ErrStopped`, a cancelled ping). A Starter interrupted by the start timeout is waited for until the deadline and stopped when it succeeds late.
  - `otel/nanotrace`: the global install moved to `Installer.Start`, and `Provider` is a start-less Stopper, so a build that fails after `NewProvider` still flushes its spans. A bound `endpoint` or `traces_endpoint`, from the environment or a YAML layer, reaches the exporter (`/v1/traces` joined to the base endpoint, as the specification says); an endpoint that is not an http or https URL fails the build. On fx, register both `Lifecycle[*nanotrace.Provider]` and `Lifecycle[*nanotrace.Installer]`.
  - The nano module constructors give a zero duration or size its default (`nanopg`: port, `max_open_conns`, `conn_max_lifetime`; `nanolock`: lease and heartbeat, and a negative duration or a lease shorter than two heartbeats is refused before pglock sees the pool; `nanopprof`: an empty `addr` is 127.0.0.1:6060). `nanolock.NewClient` accepts the otelsql pool of `nanopg`.
  - `pg/nanomigrate` waits for the migration lock of another instance with a poll that a stop interrupts (`ErrStopped`), and discards a connection whose lock release it cannot confirm.
  - `nano gen wire` names colliding `Overrides` and `Components` fields after their packages whatever the graph order (`NanopgDB` and `SQLDB`, `NanoserverServer` and `NanopprofServer`), and a slice of a name ending in `s` gets `List` (`ContextAttrsList`).
  - `nanohttp.NewRouter` registers a catch-all `/` on the mux and answers 404 and 405 from it: a hit costs what a bare ServeMux costs. Wrapping one mux twice panics.
  - `pkg/httputil/errorenvelope`: behind `core/log.HTTPMiddleware`, an error after a stream started appends its frame without writing a second status, and the `request failed` line reports the status the client received.
### Fixed
- `modules/migrations` (and the new `pg/nanomigrate`) give their connection back to the `*sql.DB` pool after a run. Before, each run kept one connection checked out for the life of the process.
- `modules/migrations`: `validate: false` turns the down-file warnings off also while migrations are enabled.
- The regressions that [docs/benchmarks/v0.23.0-beta.1.md](docs/benchmarks/v0.23.0-beta.1.md) measured (the report shows the numbers before and after the fixes, `-count=10` on the same machine): `nanohttp.NewRouter` hit 468 ns to 201 ns (bare ServeMux 201 ns), 404 13.3 µs / 353 allocs to 2.98 µs / 66, 405 7.0 µs / 150 allocs to 1.78 µs / 31; `core/log` request summary 3.65 µs / 27 allocs to 2.35 µs / 16 (zerolog 1.75 µs / 21), one log line 2.91 µs / 12 allocs to 2.10 µs / 10, the 500 error path 3.16 µs to 2.58 µs; `secret.IsKey` on a public key about 80 ns to 13-25 ns; scanning 1000 rows into `functional.Option` fields 1.79 ms / 18,619 allocs to 1.34 ms / 17,119 (pointer fields 1.20 ms / 15,619).

### Deprecated
- Every fx module in `modules/` (including `modules/httpserver.StrictErrorHandler`), `app/`, `pkg/fxlog` and `pkg/httputil/requestlog`. Each package doc has a `Deprecated:` paragraph that names the replacement, so gopls and staticcheck (SA1019) flag new imports. They keep working in the beta. A consumer that runs staticcheck adds a scoped SA1019 exclusion for these import paths until it migrates (see the upgrade notes in [RELEASING.md](RELEASING.md)). `modules/nanofx` is not marked: it is the bridge a service migrates through.

### Known risks: two implementations of each capability
Each nano module is a separate implementation, not a wrapper of its fx module (design B3 slips past this beta; see the [decision log](docs/decision-log.md)). Do not mix the values of the two packages in one service. The behaviour differences are in [docs/modules.md](docs/modules.md#differences-from-the-fx-modules). The ones that can surprise a service:
- `redis/nanocache.ErrCacheKeyNotFound` and `modules/cache.ErrCacheKeyNotFound` are different values. `errors.Is` across the two packages is false.
- `pg/nanopg` quotes every DSN value; `modules/postgres` does not.
- `pg/nanomigrate` succeeds on an empty migration directory; `modules/migrations` fails.
- `redis/nanocache.EvictPattern` uses `SCAN`; `modules/cache` uses `KEYS`.
- `redis/nanocache` escapes `:` and `\` in key parts; `modules/cache` does not. A part that holds either character is a different Redis key in the two packages.
