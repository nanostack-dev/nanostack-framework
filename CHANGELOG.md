# Changelog

One section per module and version, newest first. Each section uses Added, Changed, Deprecated, Removed and Fixed. [RELEASING.md](RELEASING.md) gives the release steps and the upgrade notes.

## gen/v0.23.0-beta.8

A fix release of `gen` only. It requires root `v0.23.0-beta.4`, `db/v0.23.0-beta.4` and `pkg/functional/v0.23.0-beta.1`, which do not change. `gen/v0.23.0-beta.7` is retracted: upgrade straight to this release ([RELEASING.md](RELEASING.md#upgrade-to-the-nanostack-cli)).

### Fixed
- The repo step treats a file with the old header, "Code generated by nano gen repo", as its own. In `v0.23.0-beta.7` four checks in the repo step (its own files, the derived files, the search builders and the forward stubs) matched only the new header, so the first run after an upgrade read the derived files and search builders a service already had as hand-written and reported each of their methods as declared twice.

## gen/v0.23.0-beta.7

The CLI is `nanostack`, and an overlaid load no longer type-checks every dependency from source. It requires root `v0.23.0-beta.4`, `db/v0.23.0-beta.4` and `pkg/functional/v0.23.0-beta.1`, which do not change. Upgrade with [RELEASING.md](RELEASING.md#upgrade-to-the-nanostack-cli).

### Changed
- **Breaking:** the CLI is `nanostack`, in `gen/cmd/nanostack`. `nano` named macOS's `/usr/bin/nano` (pico) too: a bare `nano gen` opened the editor on a file called `gen` and waited for a terminal. A service changes its `tool` directive and runs `go tool nanostack gen`. Every file a step writes now starts with "Code generated by nanostack gen"; the pipeline still treats a file with the old "Code generated by nano gen" header as its own (orphans, the db step's directory scan, the repo step's own files) and rejects a `//go:generate` line that runs either name.

### Fixed
- `nanostack gen` no longer parses and type-checks every transitive dependency from source on each load. go/packages distrusts all export data once a load has an overlay, and every step after the first loads with one, so a run on echopoint made 43 such loads: a 10 to 14 GB heap and over two minutes of CPU. `gopkg.Load` takes the export data go list builds with the overlay applied and type-checks only the root packages from source. The same run peaks at 0.9 GB and takes 44 s.

## gen/v0.23.0-beta.6

Search in `nano gen repo`. It requires root `v0.23.0-beta.4` and `db/v0.23.0-beta.4`. `gen/v0.23.0-beta.4` and `gen/v0.23.0-beta.5` were fix releases of the `gen` module only, so this release of `gen` is `gen/v0.23.0-beta.6`. Pin the CLI with `go get -tool github.com/nanostack-dev/nanostack-framework/gen/cmd/nano@v0.23.0-beta.6`. [RELEASING.md](RELEASING.md#upgrade-from-v0230-beta3) gives the upgrade steps.

### Added
- `nano gen repo` binds the request body of a search that declares `nanorepo.API[Body]()` both ways against `API.Spec` (A1 to A10 of [ADR 0027](docs/adr/0027-search-in-the-db-module.md)) and writes its API mapper `<Name>SearchFromAPI`: filters with their conventional or `API(...)` property names, the three `Range` bound kinds and a one-sided `Range`, `SortKey(...).API(...)` names and aliases in the `sort_by` enum, `APIDirection` for a `sort_direction` with no `sort_by`, `IgnoresFullText`, `APIHandWritten`, and the page limits. A mapper whose handler is in another package goes there, in `<search>_search_api.gen.go`. The pipeline passes `API.Spec` and the new `API.SortByDirection` (`"ASC"` or `"DESC"`, required when a search body has `sort_by`); the single run takes `-spec` and `-sort-by-direction`.
- `nano gen repo` proves the tenant coverage of every search ([ADR 0027](docs/adr/0027-search-in-the-db-module.md), design S6). A column of `Postgres.Scopes` is a hard scope, scoped only by `Scope`, `ScopeOrNull` or `ScopeNull`. The new `Postgres.ContextScopes` registers, per column, the function that scopes a context column (`{Column: "workspace_id", Func: "example.com/app/internal/db/workspacescope.Filter"}`); such a column is scoped only by `ScopeFunc` with that function. Each table instance of the read set and of each subquery is covered by a direct scope (not on the nullable side of a `LEFT JOIN`), an `ON` or correlated `WHERE` conjunct that equates a tenant column with a covered one or with a field of the scope value, a declared foreign key from or to a covered instance, or, for the searched table, an `INNER JOIN` path. A conjunct under an `OR` counts for nothing, and each alias is its own instance. `Unscoped` needs another covered hard tenant column of the same instance. A run reports an uncovered tenant column or instance, `ScopeFunc` on a hard scope or with an unregistered function, `Scope` on a context column, a column scoped twice or two scopes of one field name, a direct scope on a `LEFT`-joined table, a subquery correlated on no declared foreign key or reading a table with the name of an outer instance, and an unkeyed literal of a generated scope struct in the package. `nano gen` writes `nanogen/search-exemptions.txt`, one line per `Unscoped`, `ScopeOrNull`, `ScopeNull`, coverage through a referenced row, `IgnoresFullText` and `APIHandWritten`, and `-check` reports it stale. `-explain` prints how each instance is covered. `nano gen repo` takes `-context-scopes column=importpath.Func`.
- `nano gen repo` writes `FilterExists` (an `Exists` field on `searchexec.NewExists` or `NewExistsFold`, correlated on the declared foreign key of the link column to the searched table) and checks the child as a subquery instance. A `From` function may put the scope value in an `ON` clause also when the scope is one value (`postgres.UUID(s)`).
- `nano gen repo` writes `SortExpr` keys ([design S9](docs/adr/0027-search-in-the-db-module.md)): the key is a package variable `<spec><Field>Key` built with `keyset.IntExprKey`, `FloatExprKey`, `StringExprKey` or `TimeExprKey` (the `Nullable` form for a pointer field), named `<row>.<field>`, and the spec selects its projection for every order. `DefaultSortExpr` names it. A run reports a Row with no such field or a field of another type, a non-pointer field for an expression that can be NULL (not a top-level `COUNT` or `COALESCE(..., <literal>)`), and a subquery that reads a column instead of an aggregate.
- `nano gen repo` generates an interface method that takes a declared search, `SearchX(ctx context.Context, q XSearch) (search.Result[D], error)`, as one call to the new base hatches `search` or `searchPage` (unexported generic methods on `transactor.Search` and `SearchPage`) with the mapper of `Map` or `MapPage`: a function, or a method expression called on the one field of the implementation of its receiver type. A hand-written method wins, and must run `q.Query`, unassigned, through `searchexec.Resolve`, `Run`, `RunPage`, `transactor.Search`, `SearchPage` or the hatches with its own `ctx` and the search's spec. A run reports a `SortHandWritten` sort on a generated method, a hand-written method that skips the declared scope, a promoted method that takes a search, an implementation that does not embed its base, a `Map` receiver type of zero or two fields, a result that is not `search.Result` of the mapper's output, and, in a package that binds an interface, a declared search that no method takes.
- `nano gen repo` writes the builder of each `nanorepo.Search` into `<file>_repo.gen.go` of the declaring file, also for a file that declares only searches ([ADR 0027](docs/adr/0027-search-in-the-db-module.md)). The builder is `<Name>Search`, an immutable query of `db/searchexec`. Its scope value is the type of the column of its one `Scope` (`NewItemSearch(tenantID uuid.UUID)`), a struct `<Name>Scope` with keyed fields only for two or more `Scope` and `ScopeOrNull` options (one field per option, named after its first column), or `struct{}` with no field (`NewTenantSearch()`). The sort enum `<Name>Sort` has one constant per `sort_by` value: the column name of `Sort`, each API name of `SortKey(...).API(...)`, and the name of `SortHandWritten`. The spec variable `<name>Search` is built with `searchexec.DefineSpec`: the `From` function (a `From` function that takes a value must take the scope value, also `struct{}`), the columns that the Row selects, `ScopeEq`, `ScopeOrNull`, `ScopeNull`, `ScopeFunc`, the `Unscoped` record, the conditions, one keyset key per sort (text, uuid, inet, enum in declaration order, timestamptz, timestamp, integer, real and double; the `Nullable` form for a nullable column, with `NullsFirst` or `NullsLast`), the tiebreak, the default sort and the default limit (20 when there is no `DefaultLimit`). Each filter gets one accessor whose field type follows its operators: `Eq`, `In`, `Eq` and `In`, `InFold`, `Contains` and `ContainsAny`, `Present`, `Range`, and `Flag`. `Eq` and `In` on a native enum column use `searchexec.EnumLit` with the labels of the enum, so a value that is not a label matches no row. `FullText` and `FullTextExpr` make one `FullText(term)` method. A run reports a search it cannot write: a search with no tenant condition (no `Scope`, `ScopeOrNull`, `ScopeNull` or `ScopeFunc`; `searchexec.DefineSpec` would panic when the package starts), a search with no sort that has a key (`SortHandWritten` adds none), a `sort_by` value given twice, two sorts whose constants have one name, operators of two field types on one filter, a filter whose name hides a method of the builder or that two filters share, `Range` on a column that is not `timestamptz`, `Eq` or `In` on a column with no literal (such as a float, or a string column that is not text, such as `inet`), NULL placement on a NOT NULL column, a sort on a column with no key (such as a bool), a hand-written name that a builder declares, and a hand-written method of a builder that has the name of an accessor or of `FullText`. `-check` reports a stale builder, and the file of a declaring file that no longer declares a search or a binding as an orphan; a run deletes that file. The forward stub of a declaring file holds its builders, so the pipeline steps before repo type-check code that uses them, and a `From` function that takes the scope struct.
- `nano gen repo` derives the columns of a search from its Row ([ADR 0027](docs/adr/0027-search-in-the-db-module.md)). The model of the table selects its `AllColumns`, as before. A Row of its own selects the `AllColumns` of each embedded model of a table the search reads (``model.Tenants `alias:"owner"` `` for a table read under an alias) and the column of each field tagged `alias:"table.column"`, in a `postgres.ProjectionList`. So a search can read a subset of the columns and the columns of a joined table, and sort on a joined column: the key reads its Row field, and a field of an embedded model through the model (`r.Items.Name`). A field with no tag selects nothing, and is allowed only when the search has a `SortHandWritten` sort, whose hand-written key selects it. Every column of a sort and of the tiebreak needs a Row field of the model field's type. A field that reads a column that can be NULL in a result row must be a pointer: a pointer in the model, or any column of a table on the nullable side of a `LEFT JOIN`, so a `LEFT`-joined key gets the `Nullable` form. A run reports a key column with no Row field (with the field to add), a field with no tag and no `SortHandWritten` sort, a tag that names no column the search reads (with the right spelling when one matches), a field that is not exported, a field of another type than the model field, an embedded model of a table the search does not read or of an aliased table without its tag, an embedded pointer to a model, a Row that selects no column, and a field that cannot hold NULL for a column that can be NULL ([generation](docs/generation.md#repositories-nanostack-gen-repo)).
- `nano gen repo` reports `InFold` and `ContainsAny` on a column that is not text, as it reports `Contains`.
- `nano gen repo` reads `nanorepo.Search` declarations and checks them. It reads the tables a search reads (the table, or each table of the `From` function with its join kind and alias), with their `ColumnTypes`, `ForeignKeys`, `UniqueKeys` and models. Every column of a `LEFT JOIN` table is nullable, and the table of the search must not be on that side. The tiebreak is the primary key in index order, or the columns of `Tiebreak`, which must contain every column of one unique key. A partial key, or a key with a column that can be NULL, does not count, because rows with NULL repeat. A run reports: a misspelt column with the column it meant; `Contains` or `FullText` on a column that is not text (`timestamptz`, `uuid`, an enum, an array, a user type such as `public.text`), also on the child column of `FilterExists`; a table with no primary key and no `Tiebreak`; a `Tiebreak` that covers no key, is empty or names a column twice; two searches of one name; `FilterAs[V]` where V is over another type than the model field; a `DefaultSort` that is not a sort; a table that is not PostgreSQL; a table package from before `ColumnTypes` and `ForeignKeys`; a package with searches and no `nanorepo.Implement` or `nanorepo.Base`; `GoOnly` around an option that is not a filter or `FullText`; a `DefaultLimit` outside 1 to 1000; a direction or an API name that is not a constant; a blank reason in `Unscoped` or `IgnoresFullText`; a string with a control character; and an option that is not a direct call of a `nanorepo` function. `nano gen repo -explain` prints each search, and takes search names as filters ([generation](docs/generation.md)).
- `nano gen repo` reads the read set of a search as table instances: a table and its alias ([ADR 0027](docs/adr/0027-search-in-the-db-module.md)). An option can name a column of an instance with an alias, such as `table.Tenants.AS("owner").Name`. The `From` function can call a function of the package that returns the join, and nano gen repo follows it. A run reports: a column of an option on an instance that the search does not read, with the join on a declared foreign key as the fix; an expression function (`FilterExpr`, `Flag`, `Condition`, `SortExpr`, `FullTextExpr`) or an `ON` condition that reads such an instance; a call outside the allowlist in a `From` or expression function; `RIGHT_JOIN`, `FULL_JOIN` or `CROSS_JOIN`; a join whose `ON` condition does not equate every column of one unique key of the joined table that orders every row with columns of the tables before it or fields of the scope value, so that a row can repeat; a join that does not start from the table of the search; an `ON` condition that reads a table joined after it; a scope value whose type can hold a Nanostack DB value; an alias that does not match `^[a-z_][a-z0-9_]{0,62}$` or that is the name of a table; and two instances of one name in a join. A field of the scope value counts toward the key only when it comes from the parameter of the `From` function. The allowlist takes column and table references, `AS`, `INNER_JOIN`, `LEFT_JOIN`, the operators and functions that build an expression, `SELECT ... FROM ... WHERE` for a subquery, `Func` and `CAST(x).AS` with a constant SQL name, `DATE_TRUNC` with a constant time zone, and the literal constructors. It refuses `CustomExpression`, a `Token` conversion, `NewEnumValue`, every `Raw` constructor, `FromSchema`, `WithPrefix`, `WithSuffix`, any other constructor that takes SQL text, a set operation such as `UNION`, a subquery `FROM` that is not a table variable or its `AS`, a package variable or a field whose type can hold a Nanostack DB value (an interface, or a struct, map or slice of one, included), a method value, a function literal, and a call that it cannot follow. `VarChar(n)(x)` and `Char(n)(x)` are refused: use `String(x)`. An expression function must be a function of the package, passed by its name. `-explain` prints the key that keeps each join to one row, and the instances of each subquery with their join and `WHERE` condition ([generation](docs/generation.md)).

### Changed
- **Breaking:** `nano gen repo` reads `ColumnTypes()` to decide which columns of a base get `XContains` and `XEqualsIgnoreCase`: a string column that is not a key or an identifier, of type `text`, `varchar`, `char` (`bpchar` in `ColumnTypes()`) or `citext`. An `inet`, `jsonb` or `uuid` column that the model reads as a string no longer gets them, and no longer gets `X(v)` and `XIn(vs...)` either, because they compared with a text value (before, all four failed at run time). A derived method on such a column is now refused with the reason. A table package without `ColumnTypes()`, or with no type for such a column, is an error at the declaration: run `go tool nano gen db`, then `go tool nano gen repo`. A view is the exception: `nano gen db` writes no `ColumnTypes()` on a view yet, so the base of a view generates, its string columns keep `X(v)` and `XIn(vs...)`, and they get no `XContains` and no `XEqualsIgnoreCase` ([generation](docs/generation.md#repositories-nanostack-gen-repo)).
- **Breaking:** the base's `XContains(term)` calls `db/searchexec.Contains`, the substring rule of every search, and the base no longer declares `nanoContainsPattern`. A blank or white-space term now matches every row, also a row where the column is NULL (before: every row where the column is not NULL). The term is trimmed. `%`, `_` and `!` in the term match themselves, and `\` is an ordinary character. On PostgreSQL the SQL is `col ILIKE $1 ESCAPE '!'` instead of `LOWER(col) LIKE $1`: an index on `lower(col)` no longer serves it, and a trigram index on `col` does. A term that is not valid UTF-8 matches no row. On PostgreSQL, `XContains` on a column with a nondeterministic collation fails with an SQL error, because `ILIKE` refuses such a collation (before, `LOWER(col) LIKE` worked there on PostgreSQL 18): write that predicate by hand. Run `go tool nano gen repo` and commit the base.
- **Breaking:** `nano gen db` also writes `ColumnTypes()` and `ForeignKeys()` on each table type, after `UniqueKeys()`. `ColumnTypes` gives the catalogue type of each column by column name (the type name from `pg_type`: the base type at the end of a chain of domains, `_text` for a `text[]` column or an array of a text domain, the name of an enum, and `schema.name` for a type of another schema or a type that has the name of a `pg_catalog` type (`billing.status`, `public.path`)), so `nano gen repo` can tell `text` from `inet`, `jsonb` or `uuid`. `ForeignKeys` gives the foreign keys in constraint name order, with the referencing and the referenced columns in key order, and the schema of the referenced table when it is another schema. A column named `column_types` or `foreign_keys` is an error. Every table file and every `output` line of `nanogen.sum` changes: run `go tool nano gen db -fresh` (or `go tool nano gen -fresh`) and commit the result ([generation](docs/generation.md#database-nanostack-gen-db)).

## db/v0.23.0-beta.4

The db module now holds the search contract, the keyset pager and the runtime of generated searches. It requires `pkg/functional/v0.23.0-beta.1`, which does not change. All changes add API; no exported name is removed.

### Added
- `search`: `Request[F, S]`, `NewRequest` and the methods `One`, `WithFilter`, `WithFullTextSearch`, `WithSort`, `WithCursor` and `WithPagination` move here from `pkg/search`, with the same behaviour and validate tags. Use `Request` for a search that has no SQL builder (a remote call, data in memory) or that `nano gen repo` cannot declare.
- `internal/jet`: `DialectSwitch(func(Dialect) Expression)` and its typed forms (`BoolDialectSwitch`, `IntDialectSwitch`, `StringDialectSwitch`, ...). The statement's dialect selects the expression when the statement is serialized, so one value serves PostgreSQL, MySQL and SQLite. Search uses it for the SQL that differs per dialect.
- `keyset`: the db module now holds the keyset pager. It moves from `pkg/db/transactor` with the same behaviour on PostgreSQL, and the cursors stay byte for byte the same (a golden test pins them against the old pager). It holds the key constructors (`StringKey`, `UUIDKey`, `InetKey`, `EnumKey`, `TimeKey`, `LocalTimeKey`, `IntKey`, `FloatKey`, `RealKey` and their `Nullable` forms), `Order`, `OrderOf` (the strict form: an unknown sort is `search.ErrUnknownSort`), `Seek`, `Trim` and `Cursor`, and `Page`, which counts the matches and reads one page. `PageOf` is `Page` with a mapper that reads the whole page at once. `RequireWhere` refuses a page with no `WHERE` with `search.ErrUnscoped`. The executor is a parameter, and every statement runs through `query`. `Seek` and `OrderBy` write PostgreSQL SQL, so use them only in a `db/postgres` statement. `EnumKey` panics when its type name is not a plain identifier (`^[a-z_][a-z0-9_.]*$`), because the name goes into the SQL as raw text. `InetKey` refuses a cursor address with an IPv6 zone (`fe80::1%eth0`) with `search.ErrInvalidCursor`, where the cast failed in the database before.
- `keyset`: `Page` runs on MySQL, MariaDB and SQLite too, with the contract it has on PostgreSQL: the same rows, every walk complete, and the same cursor tokens. It reads the dialect from its source (a table or join of `postgres`, `mysql` or `sqlite`) and writes that dialect's SQL. MySQL and SQLite name a NULL placement only for a nullable key, so an index on NOT NULL keys serves the walk. MySQL gets the expanded seek, `CAST(? AS SIGNED)` for an integer, and an enum in its native order with an `IN`-list seek. SQLite gets a row value (an expanded seek when a key is an enum), an enum ordered by a `CASE` and compared as bytes whatever the column's collation, and a time literal in its driver's write format. So a SQLite time column must be written through the driver as a `time.Time` in UTC. `SQLiteLayout` gives a `LocalTimeKey` the text form of a column that SQL fills, for example `"2006-01-02 15:04:05"` for `CURRENT_TIMESTAMP`. A SQLite time finer than a microsecond keeps its nanoseconds: its cursor value is the pair `[microseconds, nanoseconds]`, and every other cursor value keeps its single number. A uuid is lower-case text on both. `MySQLTimestampKey` and `NullableMySQLTimestampKey` order on a MySQL `TIMESTAMP` column, `MariaDBTimestampKey` and `NullableMariaDBTimestampKey` on a MariaDB 11.5 `TIMESTAMP` (to 2106-02-07), and `LocalTimeKey` on a `DATETIME`. The MySQL zero date (`0000-00-00 00:00:00`) is a valid cursor value that sorts before every date. A cursor value that the dialect's column cannot hold is `search.ErrInvalidCursor` before any statement runs: NaN and the infinities on MySQL, NaN on SQLite, a time outside the `DATETIME` or `TIMESTAMP` range on MySQL, and a year past 9999 on SQLite. A NUL byte in a text cursor is refused on PostgreSQL only. `TimeKey` and `InetKey` off PostgreSQL, `MySQLTimestampKey` and `MariaDBTimestampKey` off MySQL, and `RealKey` on SQLite (a SQLite `REAL` is a double: use `FloatKey`) are `ErrDialect`. `Page` returns the new `ErrNoProgress` in place of a page that ends on its own cursor row, so a key that does not match the stored values cannot make a client loop on one page. The SQL on PostgreSQL and every cursor token do not change.
- `query.Executor`, an alias of `qrm.Queryable`: the executor that the query helpers and `keyset` take.
- `TableSQLBuilder.UseColumnTypes` adds `ColumnTypes() map[string]string` to each table type: the catalogue type of each column, by column name, in column order. `TableSQLBuilder.UseForeignKeys` adds `ForeignKeys()`, which returns the foreign keys of the table as `[]postgres.ForeignKey` (`mysql.ForeignKey`, `sqlite.ForeignKey`): `Name`, `Columns`, `References`, `ReferencedColumns`, and `ReferencedSchema` for a key to another schema. Both are off by default. A column whose Go name is `ColumnTypes` or `ForeignKeys` is an error.
- `metadata.Column.CatalogType`, `metadata.Table.ForeignKeys` and `metadata.ForeignKey`. `postgres.ReadSchema` fills them (`pg_type`, with the chain of domains resolved and the schema added where the name alone is not unique, and `pg_constraint`, without the copies of a key to a partitioned table). The new `mysql.ReadSchema` (`COLUMN_TYPE` and `KEY_COLUMN_USAGE`; MySQL and MariaDB) and `sqlite.ReadSchema` (the declared type and `pragma_foreign_key_list`; a key declared without its referenced columns gets the primary key of the other table, and the referenced table and columns are the names in the catalogue, not as `REFERENCES` writes them; a key to a table or a column that does not exist is an error) fill them too, and set `metadata.Table.CatalogTypesRead` and `ForeignKeysRead`. `GetSchema`, `GenerateDB` and the `jet` command leave them empty, so their output does not change. `Render` returns an error for a table without these marks when `UseColumnTypes` or `UseForeignKeys` is on.
- `searchexec`: the runtime package of generated searches, with `Contains(term, exprs...)`, the substring rule of every search. It trims the term and matches without case: `expr ILIKE $1 ESCAPE '!'` on PostgreSQL, `LOWER(expr) LIKE LOWER(?) ESCAPE '!'` on MySQL, MariaDB and SQLite. `%`, `_` and `!` in the term are literal, and `\` is an ordinary character. A blank term gives `TRUE`, never nil. Several expressions are combined with `OR` in parentheses, so a scope next to it applies to every match. A term that is not valid UTF-8, or that holds a NUL character, gives `FALSE` on every dialect. Matching follows the column's collation: SQLite, and PostgreSQL on a `"C"` or `"POSIX"` column, fold the case of ASCII letters only, and the accent-insensitive collations of MySQL and MariaDB also ignore accents.
- `keyset`: computed keys. `IntExprKey`, `FloatExprKey`, `TimeExprKey` and `StringExprKey` order on an expression, not on a column, for example a correlated `COUNT` of a row's children. The first argument is the key's name: the name in the cursor signature and the select alias that the row field maps to. It must be a `row.field` alias that matches `^[a-z_][a-z0-9_]*\.[a-z_][a-z0-9_]*$` (`widget_row.request_count`), or the constructor panics. `OrderOf` returns an error when two different keys of a search have one name, for example a computed key named after the tiebreak column. `Page` selects each computed key of the order with its alias, so the scan fills the field that the next cursor reads. `Key.Projection` returns that aliased expression: put it in the columns of a page to fill the field on every order, and `Page` does not select it twice. Another column with the alias of a computed key is an error before any statement runs. `Order.Projections` returns the aliased expressions for a query that does not use `Page`. An expression can be NULL even when its columns are NOT NULL, such as a `MAX` over no rows. A non-nullable form reads NULL as the zero value (0, the zero time, the empty string) in the order, the seek and the scan. Use the `Nullable` forms (`NullableIntExprKey` and the others, with a pointer field) when NULL must sort apart. The integer and float forms cast the expression to the type of their cursor value, per dialect: `bigint` and `double precision` on PostgreSQL, `SIGNED` and `DOUBLE` on MySQL and MariaDB, `INTEGER` and `REAL` on SQLite. The text forms run on every dialect too. The time forms cast to `timestamp with time zone` and are PostgreSQL only: a page with a `mysql` or `sqlite` source is `ErrDialect`.
- `searchexec`: the core of generated searches. `DefineSpec(SpecDef{...})` returns the `Spec` of one search; it panics at package init when the definition has no `From`, no `Columns`, no key, no tiebreak or no tenant scope (no `Scope` and no `Context` entry), when the default sort is not a key, when two keys have the same name but differ, or when the default limit is outside 1 to `search.MaxLimit`. `Query[T, Q, S, P]` is the immutable state that a generated builder embeds, with a typed scope value `P`: `New`, `Scope`, `SortBy`, `After` (a non-empty cursor clears the offset), `Offset` (a non-zero offset clears the cursor) and `Limit`. The tenant conditions are `ScopeEq` (one value for one or more columns), `ScopeOrNull` (`(col = $1 OR col IS NULL)`), `ScopeNull` (`col IS NULL`), `ScopeFrom` (a scope field that `From` puts in an `ON` clause; no `WHERE` condition) and `ScopeFunc` (a condition from the context). `Resolve`, `Run` and `RunPage` take the spec and refuse with `search.ErrUnscoped` a query of another spec, a struct literal of the builder, a zero scope value, a zero field of the scope struct (also a field that only `From` reads) and a context scope that returns nil; they refuse a page that `search.CheckPage` refuses; no statement runs before these checks. `Resolve` returns an opaque `Plan` for a hand-written method: `And` narrows the condition, `Order` adds the keys of hand-written sorts, `Run` and `RunPage` run it, `Sorts` and `Page` read it. `Run`, `RunPage`, `Plan.Run` and `Plan.RunPage` run on the executor they get: they do not read the context transaction and do not refuse a row lock. Repository code runs searches through the transactor forwarders of a later release.
- `searchexec`: the field types of generated builders. `In` (`expr IN (...)`), `InFold` (an exact match without case: `expr ILIKE $1 ESCAPE '!'` for each value, with its LIKE wildcards escaped, joined with `OR`; the database folds both sides by the collation of the column, so the answer agrees with the column also for the Turkish dotted I and on a `"C"` column; `LOWER(expr) LIKE LOWER(?) ESCAPE '!'` on the other dialects), `Eq`, `EqIn`, `TimeRange` (`Since` is `>=`, `Until` is `<=`, `After` is `>`, `Before` is `<`; a bound moves to a whole microsecond in the direction that keeps its meaning, so every PostgreSQL driver gives the same rows), `Presence` (`Present(true)` is `IS NOT NULL`, `Present(false)` is `IS NULL`), `Flag` (`Is(true)` is the condition, `Is(false)` is `condition IS NOT TRUE`, so a row where the condition is NULL counts as a row where it does not hold), `Text` (`Contains`, `ContainsAny`) and `Exists` (`EXISTS (SELECT 1 FROM child WHERE correlation AND column IN (...))`, with `NewExistsFold` for the folded form). Each has a `New*` constructor that generated code calls. `NewInFold` and `NewExistsFold` take the value type first: `NewInFold[Role](q, column)`. From Go, an empty list (`In()`, `ContainsAny()`, `Exists.In()`) matches no row. More than `search.MaxInValues` values is `search.ErrTooManyValues`, and a term longer than `search.MaxTermLength` characters after the trim is `search.ErrTermTooLong`: the field records the first such error on the query, and `Resolve`, `Run` and `RunPage` return it after the scope checks and before the page check, so no statement runs. A string value that no text column can hold (not valid UTF-8, or holding NUL) matches no row in every field, with no error: `StringLit` makes it `NULL`, and `InFold` drops it. The literals `StringLit`, `BoolLit`, `IntLit`, `UUIDLit` (`$1::uuid` on PostgreSQL, the lower-case canonical text on MySQL, MariaDB and SQLite) and `EnumLit(labels...)`, which makes a value that is not a label of the enum `NULL`, so it matches no row and PostgreSQL does not refuse the statement. A field of a builder struct literal returns the zero builder, which `Resolve` refuses with `search.ErrUnscoped`.
- `search`: `ErrInvalidSortDirection`, a client error. `searchexec.Resolve` returns it for a sort direction other than `ASC` or `DESC`, and runs nothing. Before, the sort ran as `ASC`.
- `searchexec`: `ContainsAny(terms, exprs...)` is `Contains` on each term, joined with `OR`. No terms give `FALSE`; a blank term among them gives `TRUE`.
- `searchexec`: the API helpers that a generated `<Name>SearchFromAPI` calls to turn an API request body into a builder. `Some(q, set, vs)` applies a list filter only when the list is not empty, and `Opt(q, set, v)` applies a filter only when the pointer is not nil, so in the API a property that is not sent filters nothing (from Go, an empty list still matches no row). `OrZero(body)` reads a nil body as an empty one. `APISort(q, q.SortBy, sortBy, sortDirection, def, fieldDirection)` keeps the default sort when neither is sent, sorts a `sort_by` that comes alone in `fieldDirection` (the direction the API contract states), and applies a `sort_direction` that comes alone to `def`, the field of the default sort. `APIDirection(q, q.SortBy, def, sortDirection)` does the same for a body that has `sort_direction` and no `sort_by`. The sort and direction types of the body (`~string`) convert by their values. `APIPage(q.Query, pagination)` keeps the spec's default limit when the request sends no limit (zero), and takes every other limit, the offset and the cursor as sent. The helpers do no checks of their own: `Resolve`, `Run` and `RunPage` refuse an unknown sort, a sort direction other than `ASC` or `DESC` (the new client error `search.ErrInvalidSortDirection`), a page outside the limits, a cursor with an offset and too many values, as for a Go caller.
- `searchexec`: searches run on MySQL, MariaDB and SQLite too. The source of a search, and the child of an `Exists` field, is a table or join of `postgres`, `mysql` or `sqlite`; any other value, and an `Exists` child of another dialect than the source, is `keyset.ErrDialect` before any statement runs. Each field writes the SQL of the statement's dialect. `NewLocalTimeRange` binds a `TimeRange` to a timestamp without time zone (a MySQL `DATETIME` or `TIMESTAMP`, a SQLite `DATETIME`, a PostgreSQL `timestamp`), the type of every generated MySQL and SQLite time column; `NewTimeRange` takes a PostgreSQL `timestamptz`. A `TimeRange` bound moves to a whole microsecond on PostgreSQL and MySQL; a PostgreSQL `timestamp` gets the wall clock of the bound in UTC. On SQLite the bound is the time in UTC in the text form of the driver, with every digit, so a SQLite time column must hold times written through the driver in UTC. `TimeRange.SQLiteLayout` gives the text form of a column that SQL fills, for example `"2006-01-02 15:04:05"` for `CURRENT_TIMESTAMP`, and a bound between two values of that form moves to one of them in the direction that keeps its meaning. A bound before `0001-01-02` or after `9999-12-30T23:59:59.999999Z` is the new client error `search.ErrInvalidTime` on every dialect, before any statement runs: the MySQL driver refuses a year outside 1 to 9999, and SQLite text sorts in time order for four-digit years only. A list of more than 64 values or terms (`InFold`, the folded `Exists`, `ContainsAny`) joins its matches with `OR` in nested groups of 64, because SQLite refuses an expression tree deeper than 1000 levels; the answer does not change. A search with no `WHERE` condition runs with the literal `TRUE`, not a bound argument.

### Fixed
- The SQL builder writes an alias that contains a quote or a backslash with the identifier quote character, doubled inside the alias (`AS "a""b"` on PostgreSQL, ``AS `a"b` `` on MySQL and SQLite). It also doubles the quote character in a quoted identifier, so a subquery column or a CTE name that refers to the alias agrees with it. Before, a quote in an alias or in a reference to it ended the quoted name, and on MySQL a backslash before a quote did the same; the rest of the name was read as SQL.
- On MySQL, `SELECT_JSON_OBJ` sends a JSON object key that contains a backslash as a bound argument. Before, `\'` in an alias ended the key literal, and the rest of the alias was read as SQL. The server now returns such a key unchanged; before, it read `\t` or `\n` in it as an escape.

When no provider returns a tag interface, the fix names the provider to add. A `nano.Bind` whose type lacks a method also gets the method in full in its fix.
- `nano gen config`: the `defaultenv:"NAME"` tag takes a setting's default from another environment variable. The setting reads `NAME` only when its own variable and the config files leave it unset, and then falls back to its literal `default`. The fix for two settings with one `env` suggests `defaultenv`.
- `gen/validate`: the `x-nano-unenforced: "<reason>"` schema extension accepts the unenforced features of that schema and of the schemas under it. `Result.Gaps` returns the gaps that no extension accepts and the extensions that accept nothing. `Diagnostic` has `Line` and `Waived`.
- Every generator error names its fix. Each error is a `*gen.Error` (`File`, `Line`, `Msg`, `Fix`), joined with `errors.Join`. `nano` prints `file:line: message` and an indented `fix:` line.

### Security
Beta audit fixes. Each one that changes a response or a log line is listed with the change.
- **Bounded validation errors (sec-http-1).** A request body with many violations (a 1 MiB array of empty items, an object of unknown members) built one error per violation: about 900 MB of allocation for one request. Generated validation now stops at `validate.MaxErrors` (100) plus one, skips the items of an array past `maxItems` and the members of an object past `maxProperties`. Wire change: a 422 or 400 lists at most 100 violations, and its detail says "More than 100 violations in the request body; the first 100 are listed." instead of the count. Responses with 100 violations or fewer do not change.
- **Security requirements match the router (sec-http-2).** `pkg/apisec.Resolver` matched with gorilla/mux, which treats `servers`, encoded paths and HEAD differently from the router that serves the request, so a request could reach an operation under the requirements of another one. `apisec.NewResolver` now matches as `http.ServeMux` and `nanohttp.NewRouter` do (`ExplicitHEAD` refuses HEAD on a GET route as the router does); a service on chi passes `apisec.MatchChi()`, which matches as chi's `Find` (raw path first). `modules/apisec` uses `MatchChi`. The `servers` entries are ignored. A spec whose paths conflict in ServeMux, or that has a parameter inside a path segment, fails `NewResolver` without `MatchChi`. Echopoint tests that call `apisec.NewResolver(doc)` pass `apisec.MatchChi()`. A request the resolver does not match must be refused (the doc says so); echopoint's `WithAuth` must do it before the service adopts `NewRouter` or drops its kin-openapi validator.
- **Text bodies are bounded (sec-http-3).** A `text/plain` request body of a generated nano server was read without a limit. It now reads through `nanohttp.ReadText`, under `DefaultMaxBodyBytes`, and an oversized body is a 413, as for JSON.
- **Generated code cannot be injected from the spec (sec-supply-01, sec-supply-02).** `nano gen validate` copied spec text (a `format`, a type name, a discriminator mapping, a path) into Go comments, where a line break ended the comment and the rest compiled as code. It now escapes control characters and U+2028/U+2029. A boolean enum value written `True` or `yes` is decoded as YAML decodes it, and a non-numeric value in a numeric enum is a spec error instead of generated code.
- **Dependencies (sec-supply-03).** OpenTelemetry v1.47.0 (contrib v0.72.0), XSAM/otelsql v0.44.0 and klauspost/compress v1.20.3, past the advisories that govulncheck reported as reachable. `db` and `db/tests` declare `toolchain go1.27.3`. govulncheck now reports no reachable vulnerability in any module, and CI keeps it so.
- **Readiness hides check errors (sec-core-02).** The `/readyz` body of `nano.App.AdminHandler` named each failing check with its error text, which can carry a host name or a DSN fragment. Wire change: each check now reads `ok` or `fail`. The error goes to the log, once when a check fails or its error changes (Warn) and once when it passes again (Info). Serve the admin handler on its own listener; the wire example does.
- **Redaction (sec-core-01, sec-core-04).** `secret.RedactURL` redacts the whole text of a URL that parses into a host ending in `:` or an `@` in its path or fragment (a password with an unescaped `@` or `#`), and of an opaque URL; `config.ParseURL` rejects a host that ends in `:`. `secret.IsKey` also treats the suffixes `sig`, `pwd`, `jwt` and `passcode` as secret, and judges the last segment of a bracketed key (`user[password]`, `items[0][token]`). More values are redacted in logs; none is redacted less.
- **Cache keys have one encoding (sec-db-001).** `redis/nanocache` joined key parts with `:` without escaping and passed them into a Redis glob, so `Key("a:b")` and `Key("a", "b")` were one key, and `EvictPrefix("team[ops]")` or `EvictPrefix("*")` evicted the wrong scope. A part's `:` and `\` are now escaped, `EvictPrefix` escapes the glob characters, and `EvictPattern` unlinks each SCAN page instead of one unbounded DEL. Keys whose parts hold neither character (UUIDs, hashes) do not change; others start cold after the deploy. `nanocache.New` now returns `(Cache[T], error)`: it rejects an empty prefix and a prefix with a glob character or a trailing `:` (`ErrInvalidPrefix`), and two caches must not have nested prefixes (`a` and `a:b`). `modules/cache` is frozen and keeps the old keys.
